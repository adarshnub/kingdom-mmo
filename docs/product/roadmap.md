# Delivery roadmap

The roadmap assumes a 4–6 person core team plus part-time infrastructure, legal, security, and art support. Dates start when staffing and product decisions are available.

| Phase                | Weeks | Deliverable                                                                          | Exit criteria                                               |
| -------------------- | ----: | ------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| Foundation           |   1–4 | Docs, monorepo, CI, local stack, auth, schema, contracts, Unity shell                | Clean-clone setup and first mobile-to-server request work   |
| Vertical slice       |  5–12 | City, build queue, troops, viewport, monster, march, battle, report, alliance basics | Internal Android build proves the complete core loop        |
| MVP                  | 13–24 | Research, hospital, PvP, gathering, rallies, chat, mail, events, IAP stubs           | Feature-complete internal playtest with recoverable state   |
| Alpha                | 25–32 | Heroes, equipment, alliance tech, VIP, throne, moderation, remote content            | Content-complete build passes economy and moderation review |
| Beta                 | 33–40 | Store sandboxes, anti-abuse, optimization, privacy, accessibility, DR                | 24-hour soak, security review, store readiness              |
| Soft launch          | 41–46 | India/SEA rollout, tuning, experiments, support and incident rotation                | SLOs and product guardrails hold under real traffic         |
| General availability | 47–48 | Release freeze, launch event, operational handoff                                    | No critical security/economy defects; rollback drill passes |

After launch, use two-week code releases, weekly data-driven events, monthly content drops, and quarterly capacity/security reviews.
